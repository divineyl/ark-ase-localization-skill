# 已验证案例与适用范围

记录日期：2026-10-26。这里的数字来自实际本地制作的文件级记录，不是工坊下载量或未来版本承诺。原资源、翻译整表和个人路径不包含在此仓库。

## Annunaki Genesis / AG 起源：538986229

观察到资源 profile 为 402/7。旧覆盖包有 340 个资源、475 处中文显示字段，但遗漏 Buff 状态名/说明和若干生物名称。

发现 `BuffDescription -> StatusValueModifierDescription` 中的嵌套文字。普通标准导出未覆盖该层；只读 M2 和按旧结构头宽度解析相互补充。

补全版覆盖 601 个资源、816 处显示字段。本次增加 341 处，包括 138 处状态/HUD 字段、181 处生物名称及 22 处物品/建筑显示字段。138 处状态/HUD 分为名称 66、说明 61、HUD 提示 11；再加原有制作界面 5 处，合计 143 处已识别界面字段。

所有改动资源通过定点重建、原始名称表保持、反向还原逐字节一致和独立只读导出。没有逐页进行游戏测试。`Anglerpescum`、`DodoRexy` 等专有名未强行编造译名，原始空说明保持空白。

针对这个模组使用“暴虐”翻译 Badass，巨猿/大金刚分别对应 Gigantopithecus/Megapithecus；这是案例术语选择，不要求其他模组照搬。

经验：已有物品中文不代表 UI 中文；DinoEntry、生物蓝图和状态 Buff 应分别检查。从英文原件重建显示字段，可以避开旧包对内部 DinoNameTag 的不当改动。

## Ark Nucleus：2566418613

本地游戏 Mods 目录没有该 ID，但 Windows 工坊缓存存在。正确的下一步是解压缓存，不是让用户重新找模组或把 ModName 文本当作完整 UI。

观察到 profile 为 404/10，不能沿用 402/7 的固定头偏移。界面同时使用控件实例 FText、枚举 DisplayNames、JSON 动态页面和 `LStrings` 语言表。

最终工作包覆盖 60 个资源、391 处实际修改字段；展开语言表和 JSON 后为 673 处译文记录、338 组不同原文/译文。为 243 条原有语言项提供中文，并在单独审查后补上 1 条缺失标题。英文表保留，新增中文语言项，新配置默认 ZH。

初版的 391 处修改均通过独立工具 M2 只读重新导出匹配。60 个资源反向还原逐字节一致；初版安装器在隔离副本上测试了版本拒绝、备份、复制校验和重复安装。发布初版时尚未安装到游戏，也未游戏内逐页测试。

经验：UI 短按钮不必强求中英并列。保存原文位置，避免“Label:”与“LABEL:”都译为“标签：”后无法从译文确定各自原文。现有客户端语言设置和用户自定义译文可能优先于默认 ZH。

附带通用写入器比这个一次性补丁更保守：默认不增删语言项，也不内置游戏安装器。个案上的额外修补不能未经分析自动套到新模组。

2026-10-27 后续安装排查：用户截图出现大量 `_KEY_`，核对实际启动目录后发现现装的 60 个文件仍与英文原件一致；用户确认尚未替换。随后按明确请求备份并安装 60 个汉化资源，安装后哈希全部匹配、待替换数量为 0。此时仍需重启游戏复核，不能据截图先把原因定为语言表格式错误，也不能把“已安装”当成“游戏界面已全部验证”。

后续新的游戏截图确认：即使文件已安装并重启，切换 ZH 和 EN 都仍显示 `_DINO_CATALOG_`、`_YES_` 等键名。对照语言表和蓝图读取流程，发现中文游戏资源中 `GraphLiteral` 的 `Key` 被翻译为“键”，与 JSON 表的 `Key` 字段不一致。对 7 个资源中的 22 处关联字面量身份制作模组专用测试修复，保持长度、离线检查脚本结构和逐字节反向还原，并备份后安装。之后的截图中，中英文图鉴标题、提示及按钮均显示正常。这是对该页面的实际验证，不是对模组所有功能的验证。

图鉴中的 `Can be tames:` 是另一问题：该调用经过空格移除后查找 `Canbetames:`，而主语言表缺少该项。单独添加英文和中文条目后，用户确认显示“可驯服：”。`Region #` 由另一段代码拼接，仍未完成汉化；生物名、类名和颜色名也可能来自不同数据源。

在前述 60 个资源基础上，包含语言查找修复和驯服标签的新覆盖包共有 62 个资源。隔离目录测试了从原版和旧汉化版安装、备份、重复运行、哈希校验及拒绝未知版本。独立导出、反向还原及游戏内证据各有不同范围；新增的字节码改动不应被描述为通用写入器功能或全页面已验收。
